## 用户工作方式 (2026-08-16, 原文)

> 接下来, 我的建议是, 先大量fan-out subagents, 进行充分地搜索调查研究, 我应该在research文件夹中给出了一部分初步研究资料, 具体实现细节还需要进行大量的研究和细节确认, 机制规划, 源码研究等等来进行技术选型和决策固定. 主动上下文管理, 完全不同于omp-qol中的其他部分, 是因为它本身功能不存在, 而且极为复杂繁琐, 并且需要从头进行架构设计和规划, 以及完整的实现规划, 还有给予实际使用的验证, 甚至还需要对于缓存率, 价格影响等等指标进行验证和分析 - 这些都是量很大的工作.
>
> 因此我们需要在doc文件夹中的合适路径上面, 建立对于这个模块的完整工作区文件夹, 以进行长期, 庞大, 分模块解耦, 复杂的研究规划设计工作, 来保证我们真的能够实现这个功能模块.

（范围注：本模块不是 thin-driver 暴露已有宿主能力；功能本身不存在，必须从架构、实现规划、真实使用、缓存率与价格影响一起做。活工作区在 `docs/workspaces/initiative-context-management/`，不覆盖本目录支柱原文，也不改写 `docs/researches/OMP-QOL-Complete-Research-Handoff-2026-08-09/` 冻结交接包。）
